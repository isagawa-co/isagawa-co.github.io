The Problem

SSH configs drift. Manual audits do not scale.

Your infrastructure ships across AWS, GCP, Azure, and bare metal. Each environment has SSH hardening requirements from different compliance frameworks. Manual audits take days. You find out you are non-compliant when the auditor does. Continuous compliance should not require continuous human effort.

Frameworks

Four compliance standards. One platform.

Each framework targets a different compliance need. The platform validates all four from a single pytest run.

DOD / HARDENING / MANDATORY

DISA STIG

Security Technical Implementation Guides. The Department of Defense standard for system hardening. Hundreds of individual checks mapped to STIG rule IDs, each with a severity category. Required for any system on a DoD network.

INDUSTRY / BASELINES / LEVEL 1

CIS Benchmarks

Center for Internet Security Level 1 benchmarks. Consensus-driven security baselines adopted across industries. Practical, actionable hardening recommendations that balance security with operational usability.

FEDERAL / CUI / 110 CONTROLS

NIST 800-171

Protecting Controlled Unclassified Information in nonfederal systems. 110 security controls that map to SSH configuration requirements. Mandatory for defense contractors handling CUI under CMMC 2.0.

CRYPTO / VALIDATION / FEDERAL

FIPS 140-3

Federal Information Processing Standard for cryptographic modules. Validates that SSH uses approved algorithms, key lengths, and cipher suites. Required when processing federal data at rest or in transit.

How It Works

From host config to compliance report.

The entire flow is fixture-driven. Adding a new host is a JSON file. Adding a new framework is a validator module. No code changes for new targets.

1

Host configuration

Define your target host in a JSON fixture. Hostname, SSH credentials, which compliance frameworks apply, expected packages, expected services. One file per host or environment.

2

Validator selection

The conftest reads the host fixture and loads the appropriate compliance validators. STIG rules, CIS benchmarks, NIST controls, FIPS checks. Each validator is a standalone module that composes the base SSH validators.

3

pytest execution

Run pytest. Each compliance check becomes a parameterized test case. The validator connects via SSH, executes the check command, and returns structured results with the compliance framework, rule ID, and severity.

4

Compliance report

Results include pass/fail per rule, per framework, per host. Hand the report to your auditor. Run it in CI/CD. Schedule it nightly. The output is the same every time because the checks are deterministic.

Architecture

Five layers. Strict separation.

Every validation follows a strict separation of concerns. The AI agent generates validators and tests using this architecture. The kernel enforces it.

Test (Arrange / Act / Assert)          ← pytest test cases
  └── Role (batch executor)               ← orchestrates validators
       └── Validator (one check category)   ← STIG, CIS, NIST, FIPS
            └── Task (single SSH command)    ← atomic command execution
                 └── Interface (paramiko)     ← SSH connection, retry, timeout
