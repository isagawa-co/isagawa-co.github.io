A self-building agent harness with hook-enforced governance.

Hooks at the tool-call boundary. Anchors that force re-grounding every N actions. Learn cycles that turn each failure into a mechanical rule update.

The Problem

Agents drift. Forget. Skip steps. Prompts don't fix it.

Mid-task they forget what they were doing. They skip steps they read minutes ago. They rationalize shortcuts as "more efficient." The model has already proven it will read the instruction, agree, and then violate it. Telling it harder doesn't work. Asking nicely doesn't work. The fix has to be structural.

  • How do you stop an agent from skipping a checkpoint it just read about?
  • How do you make the same failure literally impossible after it happens once?
  • How do you keep behavior consistent across hour-long sessions and context compression?

The Loop

Every session runs the same loop. No step can be skipped.

session-start, anchor, work, complete. The same cycle, every session. Anchors fire every N actions. Failures trigger a mandatory learn step. State survives restarts. Context survives compression. The agent cannot bypass any step: hooks block writes until each gate passes.

session-start -> anchor -> WORK -----------------> complete
                   ^         |                       ^
                   `-- every 10 actions <-----------'
                             |
                   failure? -> fix -> learn (MANDATORY)

The Architecture

Four moving parts. One harness.

Each part solves a specific failure mode. None of them depend on the agent following instructions. They work because they intercept actions at the tool-call boundary and check state before allowing the action to proceed.

1

Hooks

Fire at the tool-call boundary. Block writes when state preconditions fail. Append every action to an audit log. The hook isn't reading instructions: it's reading bytes. The agent can't talk past it.

2

Commands

Kernel operations the agent must invoke: anchor, learn, complete, backlog. Skill-based, so the agent calls them through a Skill interface, never directly. Each command enforces template structure and consistency.

3

Skills

Multi-step capabilities. Autonomous cycling. Task building. Production testing. Audit workflow. Each skill is an indexed file structure: entry point plus step-by-step references the agent reads at execution time.

4

State

Workflow JSON, intent chain, anchor logs. Append-only where it matters (audit trail). Mutable where it doesn't (session counters). Hash-signed for cross-machine verifiability.

Design Decision

Two-tier governance. Mechanical and behavioral.

Hooks alone are too rigid. Protocol alone is too soft. Both are necessary. The 29-lesson file is exactly the seam between them: every entry is either already a hook or a candidate to become one.

Tier 1: Mechanical

Hooks fire at the tool-call boundary. If state says needs_learn: true, every write is blocked until /kernel/learn runs. No talking past it. No prompt engineering past it. No editing state files to bypass it: that path is itself a hook-blocked write.

Tier 2: Behavioral

Every 10 actions, the anchor command forces the agent to re-read the protocol, re-read the lessons, and apply specific rules to its next action with concrete verbs. Protocol drift is a guaranteed failure mode in long sessions. The anchor reverses it on a schedule.

Hooks alone would require encoding every conceivable rule in code: impossible for a self-improving system. Protocol alone would rely on the agent following text it has already proven it will violate. Together: hooks for the rules you can enforce mechanically, protocol for the rules you can't.

Receipts

The system writes down its own failures.

An anchor catches a self-detected violation. The intent chain hashes the user's words. A recorded lesson escalates to mechanical enforcement on recurrence. All three are append-only artifacts from this workspace.

Anchor log

Every anchor archives the actions reviewed and any violations found. When backlog 129 was created by bypassing the /kernel/backlog skill, the next anchor flagged it and set needs_learn: true. The agent could not write again until the lesson was recorded.

Intent chain

Every backlog item is hash-signed. raw_input_hash is the SHA-256 of the user's literal words at /kernel/backlog invocation time. backlog_hash_after is the SHA-256 of the resulting file. Both go into an append-only chain a third party can verify.

Recorded lesson

When the /kernel/backlog bypass happened a second time (April 25 then June 8), the lesson was updated with a recurrence count and an escalation note: mechanical enforcement via PreToolUse hook is now overdue. Two failures of the same rule means human discipline lost.
